# TezzNative GUI Core

`gui` is the low-level framebuffer layer. It provides clipped pixel, rectangle,
rounded-rectangle, outline, and RGB gradient operations. Rectangles write rows
directly into the framebuffer, avoiding a bounds check and function call for
every pixel. `gui_clip_set` and `gui_clip_reset` provide a temporary
screen-space clip for pixel and rectangle-based drawing; backend text remains
rendered by the platform text path.

`tzgui` is the retained UI layer. A `TzWidgetTree` stores widgets by stable ID,
tracks damage, paints by z-order, and now supports parent-relative absolute
layout plus row and column flex layout. Flex containers support padding, gaps,
justify and cross-axis alignment; children support margins, grow, shrink, and
alignment overrides. `tree_hit_test` returns the topmost visible, enabled
hit-testable widget ID.

Widgets can use solid or vertical/horizontal gradient fills, rounded corners,
borders, shadows, text padding, and left/center/right text alignment. `tzcss`
can apply its shared box and flex properties to retained widgets with
`css_apply_widget` and `css_apply_layout`; its existing direct renderer still
provides the richer font and visual effects path.
Retained widget text is borrowed: keep a dynamic string alive until it is
replaced or the tree is deinitialized. Use `widget_add_text` when adding a
widget with text, then `widget_set_text` for updates. String literals have a
static lifetime and can be passed directly.
State colors cover hover, press, disabled, and focus feedback. Dirty redraws
expand around overlapping widget and text bounds before repainting, preserving
z-order without repainting the whole framebuffer for each small update.
Use `focus_color = -1` to disable a widget's focus outline; RGB value `0` is
available for a black state color.

## Fonts, icons, and presentation

`gui_text_style` draws UTF-8 text at an explicit pixel size and weight;
`gui_text_measure` measures it using the same face and size. On Windows the
host uses cached GDI font handles and antialiased text, with Segoe UI as the
default face. A family such as `Arial`, `Consolas`, or an installed custom font
can be selected per widget with `TzWidgetStyle.font_family`; weights use the
CSS range 100–900. Other hosts use the built-in bitmap fallback. The Windows
host opts into per-monitor DPI awareness so Windows does not enlarge an
already-rendered low-resolution framebuffer.

The retained widgets have built-in line-drawn icons: `1` menu, `2` history,
`3` mode, `4` backspace, `5` calculator, `6` close, and `7` settings. Attach one
with `widget_set_icon` or add a widget with `widget_add_icon`. `fb_set_app_icon`
sets the Windows titlebar/taskbar icon from a generated calculator, TezzNative
mark, code, or play glyph (`kind` 0–3) and primary/accent RGB colors. These
icons are generated by the host. For custom artwork, `tzsvg` loads local SVG
files or downloaded SVG text and draws cached vector paths on a `GpuCanvas`;
see [SVG_UI.md](SVG_UI.md). SVG assets are not yet accepted by the retained
widget icon slot or the Windows taskbar icon setter.

On the Windows host, `tree_present_dirty` presents the union of damaged widget
regions. GDI is flushed once per presentation, and the dirty rectangle is
mapped to the resized client area before it is invalidated. An idle event loop
can call `gui_wait_input` instead of drawing duplicate frames. The framebuffer
renderer is CPU/GDI based: it can redraw at the rate the application requests,
but does not provide GPU compositing or a v-sync guarantee.

```tn
import "gui"
import "gui_win"
import "tzgui"

gui_win.fb_set_app_icon(0, 0x6B3AF2, 0x9A82FF)
style:TzWidgetStyle
unsafe:
  tzgui.widget_style_init(&style, 0xFFFFFF, 0x171619)
  style.font_family = "Segoe UI"
  style.font_size = 24
  style.font_weight = 600
  tzgui.widget_set_style(&tree, title_id, &style)
  tzgui.widget_set_icon(&tree, history_id, 2, 22, 0x242124)
```

The retained tree also owns common input state: hover, primary-button capture,
focus order, keyboard activation, and inherited disabled/hidden state. Buttons
are focusable and hit-testable by default. `tree_process_event` routes one
`GuiEvent` and returns the activated widget ID on pointer release or Enter/
Space. Tab advances focus; Shift+Tab moves backward; arrow keys also move
through the focus order. `widget_set_focus_order` sets stable tab ordering,
while `widget_set_focusable` and `widget_set_enabled` control participation.
Hiding, disabling, or removing a subtree clears focus and pointer capture that
would otherwise point into it.

Call `gui_pump_input` once per frame before draining `gui_event_next`. The
Windows host queues mouse packets in order, preserves button transitions during
queue pressure, and keeps quick press/release input available as click edges for
immediate-mode GPU widgets. Precision touchpad scrolling is delivered as `kind = 7`; the
pointer position is in `x`/`y`, horizontal wheel delta is in `mods`, and
vertical wheel delta is in `data` (raw Win32 wheel units, where 120 is one
notch). Touch input is `kind = 8`: `key` is the contact ID, `buttons` is phase
(1 down, 2 move, 3 up), and `mods` is pressure when the host reports it (the
current Win32 touch path reports zero). Keyboard events use `kind = 1` for key
down, `kind = 10` for key up, and `kind = 9` for translated text; text `key`
values are Unicode code points. The `mods` bits are Shift 1, Control 2, Alt 4,
and Windows/Super 8.

```tn
import "gui"
import "tzgui"

event:GuiEvent
if gui.gui_event_next(&event) != 0:
  activated_id:int = tzgui.tree_process_event(&tree, &event)
  if activated_id > 0:
    // Dispatch the application's action for this widget.
```


Root widget bounds use framebuffer coordinates. A child of an absolute parent
uses `x` and `y` as offsets from that parent. Row and column containers compute
child positions from requested sizes and flex properties. A parent ID must
refer to a widget already in the tree. Layout setters update the layout and
damage state. Call `tree_layout` after building or changing a widget hierarchy;
the `tzcss.css_apply_*` helpers perform that layout pass for you.
`tree_render_dirty` paints pending regions;
`tree_present_dirty` also presents the surface.

This is the retained-layout and drawing foundation for native TezzNative
interfaces. It does not yet claim Flutter or desktop-framework feature parity:
rich text shaping, full scrolling and clipping, accessibility semantics,
platform-native controls, and GPU-backed compositing remain follow-on work.

Immediate-mode GPU windows keep a stable logical framebuffer while a user
drags the resize border. The Windows host stretches the last completed frame
during the drag, then normal rendering continues at the new client size. This
keeps the window responsive without reallocating the framebuffer for every
`WM_SIZE`. Retained applications can call `fb_sync_resize` and recompute their
layout once the drag completes.

On Windows, run the interactive demo from the repository root with
`tezzc run examples/dx/tzgui_core_demo.tn`. The runner selects bytecode for
`gui_win` programs until native PE programs have process-safe GUI host imports;
passing `--native` or `--fast` reports that limitation instead of starting a
program that would fault.

## High-Precision Timing, Smoothness & Animation Support

TezzNative includes native, core-level acceleration primitives to guarantee sub-millisecond frame pacing, tearing elimination, and fluid physics-based animations:

1. **High-Precision Monotonic Clocks**:
   - `gui_win.fb_time_us()` / `os.fb_time_us()`: Microsecond monotonic clock backed by Windows `QueryPerformanceCounter`.
   - `gui_win.fb_time_ms()` / `os.fb_time_ms()`: Millisecond clock for animation elapsed-time tracking.

2. **Frame Pacing & V-Sync**:
   - `gui_win.fb_frame_sync(target_fps)`: Core frame synchronizer using 1ms timer resolution (`timeBeginPeriod(1)`) and calibrated hybrid spin-wait. Returns actual measured delta-time `dt_ms`.
   - `gui_win.fb_vsync()`: Vertical blank synchronization leveraging native Windows Desktop Window Manager (`DwmFlush()`).
   - `gpu_render.gpr_canvas_end()` automatically engages `fb_frame_sync` using the canvas `fps_cap` setting for rock-solid 60 FPS or 120 FPS rendering.

3. **Physics-Based Spring & Tween Animations**:
   - `tween.TzSpring`: Damped harmonic oscillator with sub-stepped numerical integration (`fb_spring_step`).
   - Supports natural spring physics (custom stiffness, damping, target convergence) without integer truncation stalls.
   - Retained widgets support animated bounds transitions with easing curves via `tzgui.widget_animate_bounds(&tree, id, ...)` and `tzgui.tree_animate_tick(&tree, dt_ms)`.

4. **Hardware-Accelerated Framebuffer Blitting & Compositing**:
   - 1:1 direct `BitBlt` presentation avoids GDI stretching penalties during standard presentation.
   - `fb_composite_rect`: In-place 32-bit ARGB alpha blending (`(sr * a + dr * (255 - a)) >> 8`).
   - `fb_gradient_v` and `fb_gradient_h`: Vectorized horizontal and vertical gradient rendering directly in the C host.
   - `fb_fill_rounded`: Circular corner radius calculation running at native C speed.
